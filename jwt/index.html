JWT デコード

JWT（JSON Web Token）は「ヘッダ.ペイロード.署名」の3つをドットでつないだ文字列です。貼り付けると中身と有効期限（exp）を日本時間で表示します。署名の検証は行いません。

このページの解説とよくある質問を読む

入力

入力した内容は送信されません。 解析はこのブラウザの中だけで完結します（サーバーがありません）。

画像はここにドラッグ＆ドロップ

スクリーンショットは Ctrl+V で貼り付けできます。入力は保存しません（再読み込みで消えます）。

JWTの構造

xxxxx.yyyyy.zzzzz のように、ドットで区切られた3つの部分からできています。 前の2つはBase64URLでエンコードされたJSONです（暗号化ではありません。誰でも読めます）。

部分中身例
Header署名アルゴリズムとトークンの種類{"alg":"HS256","typ":"JWT"}
Payloadクレーム（利用者ID・期限・発行者など）{"sub":"123","exp":1700000000}
SignatureヘッダとPayloadに対する署名バイナリ（Base64URL）

よく使うクレームと時刻の読み方

クレーム意味注意
exp有効期限UNIX時刻の秒。10桁なら秒、13桁ならミリ秒
iat発行時刻同上
nbfこの時刻より前は無効同上
iss / aud発行者 / 対象取り違えると別サービスのトークンを受け入れてしまう
sub利用者の識別子メールアドレスが入っていることもある

exp をミリ秒で入れてしまう実装ミスはよくあります。10桁なら秒、13桁ならミリ秒です。 このツールは日本時間に直し、現在時刻と比べて期限切れかどうかを表示します。

「デコード」と「検証」は別物

デコードは中身を読むだけ、検証は署名が正しいかを確かめることです。デコードだけでは改ざんを検出できません。 このツールはデコードのみで、署名の検証は行いません（鍵を預かる必要があり、ブラウザ内で鍵を扱う設計にしていないため）。 本番の検証は、必ずサーバー側で、鍵やJWKSを使って行ってください。

なお、JWTはそれ自体が認証情報です。パスワードと同じ扱いで、外部のサービスに貼るのは避けてください。

このツールでできること

  • ヘッダ・Payloadを整形して表示し、有効期限を日本時間と「あと何日」で示します
  • 期限切れ・nbf 前・exp がミリ秒、といった不自然な値を指摘します
  • PayloadにメールアドレスやAPIキーらしき値があれば、マスクして表示します（既定ON）
  • 署名部分は中身を出しません（長さと方式のみ）

このツールの安全性

解析はすべてブラウザの中で行います。サーバーが無いので、入力した内容が送られる先がありません。 配信側の CSP（Content-Security-Policy）で fetch / XMLHttpRequest / WebSocket / sendBeacon を禁止しており（connect-src 'none'）、ビルド時に scripts/check-no-network.mjs が送信 API の混入を検査しています。 入力は保存しません（再読み込みで消えます）。一度読み込めばオフラインでも動きます。

このページの判定は決まったルールによるもので、AI（LLM）は使っていません。同じ入力なら同じ結果になります。 マスキングには取りこぼしがあります。共有前の目視確認をおすすめします。

よくある質問

署名鍵なしでデコードできますか？

できます。HeaderとPayloadはBase64URLでエンコードされているだけで、鍵は不要です。ただし署名が正しいかどうかは分かりません。

期限切れかどうかを判定してくれますか？

はい。exp と現在時刻を比べ、期限切れなら警告を出します。exp が13桁（ミリ秒）になっている場合も指摘します。

JWTをオンラインのデコードサービスに貼っても大丈夫ですか？

トークンはパスワードに相当する認証情報です。サーバーに送られるサービスに貼ると、そのサービスと経路にトークンが残ります。このツールは送信せず、ブラウザ内で完結します。

alg: none のトークンは危険ですか？

署名なしを意味するため、検証側が alg を信頼していると改ざんを受け入れます。受け入れるアルゴリズムをサーバー側で固定してください。

JWTの中に個人情報が入っていても大丈夫ですか？

Payloadは暗号化されておらず、誰でも読めます。個人情報や秘密を入れず、必要な識別子だけを持たせるのが原則です。

fmt は「貼るだけで何なのかが分かる」ブラウザ完結のツールです。サーバーを持たず、入力した内容を送信しません。 結果は決まったルールで判定しており、AI（LLM）は使っていません。

使い方と安全性

これは何？

意味がわからない文字列やファイルを貼ると、何なのか・どこが問題なのかを日本語で説明する道具です。 解析はすべてブラウザの中だけで行い、入力した内容をどこにも送信しません（サーバーがありません）。

できること

  • JWT・JSON・XML・HTML・CSV / TSV・ログ・メールのソース・Cookie・URL・証明書 / 鍵 の解析（日時は日本時間、列の多い表は縦横変換）
  • Base64・URL エンコード・16進ダンプ・Unicode エスケープの解除（解除した先も自動で判定します）
  • 画像（複数可）の形式・サイズ・EXIF・GPS・QR コード / バーコード
  • エラーの意味（HTTP / SMTP / よくある英語エラー）と、次にやること
  • 文字数・行数・バイト数・文字コード・改行・環境依存文字などの統計
  • 機密情報のマスク（メール・電話・APIキー・カード番号・AWS アカウントID・2段階認証のシークレットなど）

安全のためにやっていること

  • 配信元の CSP（Content-Security-Policy）で、fetch / XHR / WebSocket / beacon などの送信路を禁止しています（connect-src 'none'）。ブラウザのページ遷移そのものは CSP では止められません。
  • 解析は Web Worker で行い、画面が固まりにくいようにしています。
  • 一度読み込むと、オフラインでも動きます（Service Worker）。
  • 入力は保存しません。再読み込みすると消えます。
  • AI（LLM）は使っていません。すべて決まったルールで判定します（結果が毎回同じになります）。
  • HTML は「ソース」として表示し、ページとしては表示しません。Markdown 内のスクリプト・外部画像も無効化します。

できないこと（正直な制限）

  • 暗号化されたデータの中身は読めません（種類の推定まで）。
  • ハッシュ値は「元に戻す」ことはできません。長さからの推定のみです。
  • 英語の長文を自然に翻訳することはしません。よくあるエラーの意味を辞書で引く方式です。
  • JWT の署名検証、証明書の失効確認は行いません。
  • マスキングは取りこぼしがあります。共有前の目視確認をおすすめします。

注意

この画面は通信しませんが、貼り付けた先のサービス（チャット・メール・チケット）には内容が残ります。 秘密鍵やパスワードは、そもそも他人に送らないでください。
